# 식단 룰렛 요구사항

MVP 기획 단계에서 합의한 동작이다. 코드와 이 문서가 다르면 차이를 그대로 리포트한다(어느 쪽이 맞는지는 사람이 정한다).

## 형태
- `index.html` 한 파일에 HTML·CSS·JS를 모두 넣는다. 브라우저에서 바로 열리고, 런타임 외부 의존성(CDN, 폰트, 이미지)은 없다.
- 개발 도구(eslint, html-validate, jsdom)는 `devDependencies`로만 쓴다.
- 모바일 우선: 본문 최대 폭 약 480px, 좌우 여백 16px. 375px 폭에서 가로 스크롤이 생기지 않는다.
- 라이트/다크 모드는 CSS 변수와 `prefers-color-scheme`로 처리한다.

## 끼니와 메뉴
- 하루 식단은 아침·점심·저녁 세 끼다.
- 원판은 하나이고, 끼니 탭을 바꾸면 원판의 메뉴가 그 끼니의 메뉴 풀로 바뀐다.
- 메뉴 풀은 끼니별로 따로 있다(아침은 가벼운 메뉴). 끼니당 약 15개, 카테고리(한식·중식·일식·양식·분식)마다 최소 2개.
- 원판에서는 같은 카테고리가 이웃하지 않게 번갈아 배치한다.

## 후보 계산 (`getCandidates(meal)`)
1. 선택한 카테고리에 속한 메뉴만 남긴다.
2. 최근 3일(어제부터 사흘 전까지) **확정된** 히스토리에 있는 메뉴를 뺀다. 오늘 기록은 제외 기준이 아니다.
3. 오늘 다른 끼니에서 이미 뽑은 메뉴를 뺀다(같은 날 중복 방지).
4. 1단계 결과가 0개면 안내 문구("…메뉴가 없어요. 필터를 바꿔 보세요.")를 보여 주고 SPIN을 비활성화한다.
5. 2~3단계 뒤 0개면 제외 규칙을 풀고 1단계 결과를 쓰며, "최근 메뉴 제외를 잠시 풀었어요" 안내를 보여 준다.

## 회전
- 당첨 칸을 먼저 균등 랜덤으로 뽑고, 그 칸 중앙 근처(약간의 jitter)가 12시 방향 포인터에 오도록 목표 각도를 역산한다.
- 최소 5바퀴 이상, `easeOutCubic`으로 약 4초 감속한다. `prefers-reduced-motion`이면 약 0.8초.
- **포인터가 가리키는 칸의 메뉴 = 식단 카드에 들어가는 메뉴**여야 한다. 이 앱에서 가장 중요한 불변식이다.
- 회전 중에는 SPIN, 탭, 필터, 식단 카드, 확정, 초기화 버튼이 모두 잠긴다.
- canvas 해상도는 `devicePixelRatio`만큼 키운다.

## 오늘 식단과 확정
- 뽑은 결과(draft)는 메모리에만 있다. 새로고침하면 사라지되, 오늘 이미 확정한 식단이 있으면 그것으로 시작한다.
- 끼니마다 몇 번이든 다시 돌릴 수 있고, 다시 돌리면 그 끼니 칸이 교체된다.
- 식단 카드의 칸을 누르면 해당 끼니 탭으로 이동한다.
- "오늘 식단 확정"은 세 끼가 모두 채워졌을 때만 활성화된다. 확정했을 때만 히스토리에 저장한다. 같은 날짜로 다시 확정하면 덮어쓴다.

## 히스토리와 저장소
- localStorage 접근은 모두 try/catch로 감싼다. 저장이 막혀도 화면은 동작한다.
- `mealRoulette.history`: `[{ date: 'YYYY-MM-DD', breakfast, lunch, dinner }]`, 최신 날짜가 앞.
- `mealRoulette.filters`: 선택한 카테고리 배열. 기본값은 전체 선택.
- 저장 키 이름을 바꾸면 기존 사용자의 기록이 사라지므로 바꾸지 않는다.
- 히스토리 목록은 최신순으로 보여 주고, 오늘 기록에는 "오늘", 최근 3일 기록에는 "제외 중" 배지를 붙인다.
- "기록 초기화"는 확인 대화상자를 거친다.
